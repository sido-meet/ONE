# 产品需求 PRD · 草案 0.1

## 定位

ONE 是以个人对话与工作区为核心的桌面 Agent 环境。用户始终拥有对话、任务、笔记、日程和产物；不同 Agent 负责不同阶段的执行。ONE 本体是 Agent 本体：它提供对话、会话与能力接口，宠物和桌面端都只是它可插拔的本地呈现形式。

首位目标用户是你自己：在开发、安排日程和记录想法之间频繁切换，希望少开几个互不相通的 AI 窗口。初期是单人单设备，不含账号、多租户和协作。

## 需要解决的问题

1. 切换 Agent 时难以延续工作：ONE 保留规范化历史，并显式准备交接上下文。
2. 聊天结果与日历、笔记脱节：同一能力同时有聊天入口和可操作的界面。
3. 临时需求启动成本高：宠物唤起对话条，必要时再展开桌面端。
4. 运行过程不可判断：清楚区分正在回复、等待授权、工具执行、失败与取消。
5. 呈现形式和本体被绑死：任何一个窗口成了宿主，关掉它其余就失效，"默认只装宠物、桌面端可选"无法成立。

## 产品原则

- 本体是唯一的，呈现形式是可插拔的。宠物和桌面端互为对等，谁都不持有状态。
- 客户端之间不直接拉起对方：请对方做事经本体转发，因此"没装""没运行"都能给出明确错误。
- 小窗适合短操作；长任务可移入桌面端，不让用户丢失上下文。
- 每个工具操作展示输入、目标与结果；失败不能呈现为成功。
- 日历创建不等于设置系统提醒。系统通知接入后再承诺提醒。
- 不宣称跨 Agent 共享隐藏状态；交接的是可解释的历史和产物。
- 取消不会自动撤销已发生的文件或日程修改；撤销是单独命令。

## 版本范围

**0.0.1 初始化（已完成）**：前端工程、内存会话、模拟流式输出/取消/切换、文档与工程检查。

**0.1 UX 原型**：ONE 本体独立进程持有唯一状态；宠物与桌面端是对等的可插拔客户端，默认装宠物、桌面端可选；宠物 + 对话条（状态云与输入条，不显示聊天历史）、命令行客户端；模拟日历与笔记、完整状态反馈。日历先做日列表/周视图，笔记先做列表与纯文本编辑；不做富文本协同。

**0.2 本地数据**：SQLite、重启恢复、导出、版本迁移、备份。浏览器内存模式保留为快速演示入口。

**0.3 真实聊天**：一个模型提供方、密钥安全存储、流式/超时/取消、用量记录。

**0.4 Agent 接力**：验证并连接一个外部 Agent，再加入第二个；交接摘要可见可编辑。

**0.5 能力与扩展**：日历/笔记领域实现和 MCP 适配，有限的官方插件生命周期。

不承诺按日期交付；按阶段验收。移动端、云同步、团队协作、Wasm、第三方市场、自动多 Agent 并行、复杂自动路由均暂缓。

## 验证目标（目标值，尚未测量）

- 新用户在无需说明的情况下，3 分钟完成“发消息 → 换 Agent → 继续”。
- 5 次切换实验均保留原对话，零重复历史和串线。
- 已启动应用中宠物唤起小窗 p95 小于 300ms；测试时记录机器配置。
- 预览、确认、失败、取消四种状态均可辨认。
- 以访谈与本地记录验证，不默认开启遥测。性能阈值在首轮实测后修订。
