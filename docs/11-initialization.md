- **宠物接入本体**：实机启动后本体名册里出现 `kind: pet`，能力为 `pet.state` / `pet.bubble.open` / `pet.show` / `pet.hide`。

- **拖拽**：实机从屏幕右下角拖到屏幕中部，窗口跟随移动。
- **右键菜单**：实机弹出「打开 ONE 桌面端 / 重新启动 ONE 本体 / 退出」三项。
- 前端 `pnpm check` 0 错误 0 警告。

### 本轮修掉的真实缺陷

1. **壳与本体的管道读写死锁**（阻塞级）：`File::try_clone()` 在 Windows 上走 `DuplicateHandle`，读写两端是同一个文件对象，同步 I/O 被串行化。读取线程一停在 `ReadFile`，写端就永远发不出去；而本体在收到第一帧前不会主动说话，于是握手静默卡死。症状极具迷惑性：管道连上了、名册里却没有这个客户端。改用 `PeekNamedPipe` 轮询让读端永不停在读调用里。
2. **对话条带系统标题栏和窗口菜单**：`app.set_menu` 会在每个窗口客户区画菜单栏。菜单改为只挂客户端自己的主窗口，对话条改为无边框透明。
3. **宠物右键菜单只剩「退出」**：右键弹窗单独造了一份清单。改为与窗口菜单共用 `pet_menu()`，并加测试要求每个菜单项都有处理分支。
4. **启动宠物会闪一个黑框**：壳是 GUI 子系统，但 `node` 是控制台程序，父进程没有控制台时 Windows 会给它新分配一个。加 `CREATE_NO_WINDOW`。
5. **对话条一聚焦就弹自动填充下拉**，盖住状态云。输入框加 `autocomplete="off"`。
6. **一个客户端进程里的每个窗口都自称宠物**：宠物窗口和对话条窗口共用同一根管道、也就是同一个会话，但两个窗口各发一次 hello、各自注册同一套能力，本体收到能力调用时会有两个窗口抢答。壳改为只给客户端自己的主窗口声明能力，对话条只拿状态。
7. **宠物身上一直压着菜单栏文字**：菜单挂到了宠物窗口上，而宠物窗口无边框透明，Windows 就把菜单栏画进那块 128×128 的客户区里。不是右键弹窗，是常驻的菜单栏。改为只有带标题栏的窗口（桌面端主窗口）挂菜单，宠物菜单只以右键弹窗出现，键盘用菜单键 / Shift+F10。

（另外一度以为对话条右侧有滚动条，实测是后面某个程序窗口的滚动条透过透明区域被看见，不是本项目的问题。固定尺寸的悬浮条仍加了 `overflow: hidden` 兜底。）

### 冷启动实测

杀掉本体和客户端后直接启动宠物：

- 宠物自动拉起本体（约 1.25 秒后出现在名册里，主要是 node 冷启动），无控制台窗口弹出。
- 本体日志只有一次「客户端 pet 接入（pet.state、pet.bubble.open、pet.show、pet.hide）」。

启动顺序也已调整为 `start_bridge` → `start_core` → `build_windows`：先起后端再摆窗口，否则用户会先看到一个写着"本体未连接"的宠物。

### 自动化验证手段与边界（更正上一轮结论）

上一轮写的"合成鼠标事件进不了 WebView2 的 DOM"**不准确**。先 `SetForegroundWindow` 把目标窗口置前，再用 `mouse_event` 发左键/右键，WebView2 会正常收到：单击呼出对话条、右键弹菜单都已用它验证过。仍然进不去的是**纯键盘焦点链**与真实 IME 组字，这类只能人工验证。

截图辅助脚本 `scripts/shot.ps1` 会列出所有 `Tauri Window*` 的窗口与坐标，可用来定位窗口；`scripts/crop.ps1` 裁剪局部。注意桌面上若有别的程序开着悬浮层，会盖住截图里的菜单，看起来像我们的菜单画坏了。
