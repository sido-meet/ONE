# 交互与视觉设计

这是开发可用的设计规格，不是最终品牌稿。主窗口、宠物与小聊天框按下列规格已实现；日历/笔记只有契约，界面仍按草案继续开发。

## 信息架构

```text
桌面宠物
 ├─ 单击：小聊天框
 ├─ 拖动：移动宠物
 └─ 菜单：打开 ONE / 隐藏宠物 / 退出
小聊天框
 ├─ 最近对话与 Agent
 ├─ 消息与工具卡片
 └─ 展开：主窗口同一对话
主窗口
 ├─ 对话（默认）
 ├─ 日历
 ├─ 笔记
 └─ 设置（Agent 连接、外观、数据）
```

Workspace、插件管理先放到后续设置页面。当前“项目起点”是初始化说明页，正式 0.1 可移至帮助入口。

## 三种窗口

| 窗口   | 初始尺寸建议（逻辑像素）   | 行为                                                                                                           |
| ------ | -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| pet    | 128 × 128                  | 透明、无边框、置顶；底部拖拽条拖动，圆形区域单击打开对话条                                                     |
| bubble | 380 × 168                  | 不是聊天窗：上方状态云（工作中是点点点与截断回答），下方一根输入条；默认在宠物下方，空间不足翻到上方；Esc 隐藏 |
| main   | 1200 × 820，最小 760 × 600 | 常规窗口；同一对话跨窗口连续                                                                                   |

尺寸是起点，必须验证 100%/150%/200% DPI、多显示器、负坐标、任务栏边缘。初期不实现全局点击穿透；之后只对透明非交互区域单独验证。关闭小窗仅隐藏；退出应用必须停止或明确处理运行中的任务。

多窗口不能各自创建独立 MockClient 后声称同步成功。先实现权威状态源与命令代理，再验证展开/收起；详细见架构文档。当前实现：pet 圆形区域单击打开 bubble、右键弹出原生菜单（打开 ONE / 打开小聊天框 / 隐藏宠物 / 退出），底部拖拽条移动窗口（聚焦后方向键也可移动，Shift 为 1 像素微调）；bubble 只是"云 + 输入条"，不含聊天历史与 Agent 选择器，Esc 或 ✕ 隐藏，输入条左侧拖拽条可移动。定位默认在宠物下方，垂直空间不足时翻转到上方，并夹在工作区内。拖拽条与可点击区域不重叠，避免按下即拖拽吞掉单击。**未实机验证**：多显示器、DPI 缩放与拖拽手感；定位算法有 Rust 单测覆盖，视觉与手感仍需人工验收。

## 必须设计的状态

| 组件   | 状态                                                         | 用户反馈                               |
| ------ | ------------------------------------------------------------ | -------------------------------------- |
| 宠物   | idle / hover / working / attention / error                   | 轻量变化；不能只靠颜色区分             |
| 对话   | empty / ready / streaming / failed / cancelled               | 空态引导、停止按钮、错误详情、重试入口 |
| Agent  | mock / disconnected / connecting / ready / unavailable       | 清楚标注连接状况；不可用不静默回退     |
| 工具卡 | draft / awaiting-confirmation / running / succeeded / failed | 明确输入和影响范围；重试沿用幂等键     |
| 数据页 | empty / loading / ready / error                              | 空态操作、加载反馈、恢复方案           |
| 交接   | preparing / ready / failed                                   | 交接摘要预览，失败保留旧 Agent         |

这些状态是设计要求；初始化仅实现 empty、模拟 streaming、cancelled、错误文案与 mock 状态。不要为未实现的功能展示成功样式。

宠物当前实现 idle / hover / working / error 四态，并在形象下方显示状态文字（不依赖颜色）；attention 留给后续"需要确认的提醒"场景。对话页尚未实现 failed 与重试入口，小聊天框已实现服务不可用提示。

## 核心流程

### 聊天与 Agent 切换

发送 → 用户消息入历史 → Run 启动 → 临时增量 → 完整助手消息 → Run 结束。运行期间禁用 Agent 切换；用户可先停止，再切换。切换写系统事件，不重新创建对话。新 Agent 只处理后续 Run。

输入支持 Enter 发送、Shift+Enter 换行；中文输入法确认候选字不触发发送。流式输出只在用户接近底部时自动滚动；用户上翻时显示“有新回复”入口。每个对话草稿独立保存（P06），当前骨架切换会清空未发送输入。

### 日程

用户说“明天下午三点面试” → 生成操作草稿 → 显示绝对日期、时区、默认时长 → 用户确认 → 调用 calendar.create → 卡片给出结果 → 日历出现条目。模拟模式用固定示例输入，不伪装成任意自然语言解析。缺少时区/日期或存在歧义时先让用户选择。

### 笔记

“保存为笔记” → 展示标题、内容、来源 → 确认 → notes.create → 打开笔记。编辑与 AI 改写使用版本号；冲突时保留两份草稿，不覆盖较新版本。

## 视觉与组件

- 风格：安静、浅色、低打扰；绿色用于主要行动，红色只用于错误。
- 当前变量：背景 #f7f7f2、侧栏 #eeefe8、正文 #303b35、强调 #416747、边线 #e2e6dc。
- 正文字号目标 14px，说明至少 12px；当前原型部分辅助字偏小，视觉迭代时统一修正。
- 间距使用 4/8/12/16/24/32px；交互圆角 8–12px。
- 组件清单：PetAvatar、ChatComposer、MessageList、AgentPicker、RunStatus、ToolCard、ConversationList、CalendarPanel、NoteEditor、ErrorNotice、ConfirmDialog。
- 骨架已按窗口职责拆分到 `src/windows/`（MainWindow、BubbleWindow、PetWindow），共用状态来自 `src/lib/client.ts`；组件清单里除上述三个窗口外仍未逐个成组件，不提前建立大型组件库。
- 键盘可达、焦点可见、按钮有名称、错误使用可读文本。减少动态效果偏好必须生效。信息对比度目标 WCAG AA，需实际测量。
- 初期宠物用 CSS/矢量占位；最终资产需记录作者、授权、动画状态、透明背景与高 DPI 尺寸。
