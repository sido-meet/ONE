# 开发从这里开始

本规划制定于 2026-10-06，以你提供的“ONE项目方案评估”为背景。它把长期构想拆为可以逐项开发和验收的任务。尚未反馈的偏好先采用可调整默认值：Windows 优先、中文界面、个人单机、本地数据、先模拟交互。

## 项目开始前需要准备什么

| 准备项                       | 本次交付                       | 什么时候继续完善       |
| ---------------------------- | ------------------------------ | ---------------------- |
| 产品定位、目标用户、使用场景 | 产品需求文档                   | 每个版本范围确定时     |
| 功能优先级与不做清单         | 0.1 范围及后续里程碑           | 进入新里程碑时         |
| 信息架构、页面流程、状态设计 | 交互说明、布局草图、设计变量   | 宠物和小聊天框开发前   |
| 视觉方向、组件规范           | 安静的浅色桌面工作区、前端样例 | 根据你的体验反馈调整   |
| 架构和技术决策               | 模块边界、进程图、决策记录     | 接持久化/真实 Agent 前 |
| 数据和接口                   | 最小可编译契约、后续领域草案   | 对应功能动工前冻结版本 |
| 开发环境、代码库和约定       | 配置、锁文件、脚本、AGENTS.md  | 团队加入时复用         |
| 模拟数据与测试基础           | 内存会话运行时、行为测试       | 每个替换实现共享测试   |
| 安全、日志、备份             | 接入边界与实施门槛             | 真实数据进入之前       |
| 发布、安装与回滚             | 发布检查表                     | 首个可分发版本前       |

不需要一开始就准备云服务器、数据库服务、模型账号或插件市场。Rust 环境在验证桌面窗口时需要；模型账号到真实聊天阶段再配置。

## 你的第一轮开发

1. 启动当前骨架，测试新对话、发送、停止、切换 Agent，先理解 ONE 的主线。
2. 阅读 docs/01 和 docs/02，调整你想要的宠物、聊天框和主窗口体验。
3. 按开发手册补齐桌面环境，完成任务 S01（最小 Tauri 窗口实机验证）。
4. 完成 P01/P02（宠物入口与小聊天框）。先用简单几何形象，品牌资产之后再做。
5. 完成 P03（日历/笔记契约），然后 P04/P05（模拟操作闭环）。
6. 用质量文档的演示脚本走完 0.1，再决定是否进入持久化与真实 AI。

## 如何让下一位开发者或 AI 接手

可以直接给出：“阅读 README、AGENTS.md 与 docs/06-roadmap.md，完成任务 S01，按该任务验收标准验证，更新任务状态与交付记录。保留当前模拟模式。”

每次给一项边界清楚的任务：目的、输入、产出、验收、约束。复杂任务先拆成可以运行的小闭环。一个人开发也建议保持每项任务一个可审查变更。

## 完成与范围的区分

本次完成的是启动资料和基础工程。0.1 需要完整体验链：桌面宠物 → 小聊天框 → 同一对话切换模拟 Agent → 添加模拟日程/笔记 → 进入主窗口查看。尚未全部实现，勿把初始化版本当成 0.1 验收通过。
